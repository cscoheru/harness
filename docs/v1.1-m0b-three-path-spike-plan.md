# v1.1 M0b 三路径 spike 模板计划（Codex FAIL 后修订版 v0.1）

## Context

v1.1+ 周期门已开（v1.1 GA plan v0.0 DRAFT 已 commit at `bd44321`，5 DISPATCH 任务书已 commit at `d332bbe`）。但 5 DISPATCH §6.2 模板基于**未经验证的 dsh CLI 假设**起草——实际探测发现关键事实：

1. **官方 dsh 是 npm 包 `@deepseek-ai/dsh` v0.1.1-rc.2**（maintainers tianyi@deepseek.com + imccyu@gmail.com），不是 PyPI `deepseek-harness`（HenryZ838978 个人 SDK，碰巧同名）
2. **dsh 是 profile boot 框架**，顶层 CLI 只有 `web`（启 Web UI）+ `plugin`（管 plugins），**没有 chat/run/exec 子命令**
3. **Web profile 默认禁用 `tool-bash` / `tool-fs` / `tool-str-replace-editor` / `tool-goal` / `tool-ralph` 等所有"跑 A 类任务"必需的工具**
4. **默认模型 = `deepseek-v4-flash`** (provider: `deepseek-official`)；等价类三档在 dsh 内 = v4-pro / v4-flash / v4-flash-vision-exp
5. API key = `DEEPSEEK_API_KEY` 环境变量（`credentials-local` 插件 + `web-search-deepseek` 的 `apiKeyEnv` 字段）
6. Telemetry 默认 DISABLED；开了会上送 `harness-telemetry.deepseeksvc.com/v1/logs`

**问题**：5 DISPATCH §6.2 当前模板写 "dsh 命令：`dsh ...`"（抽象单姿势），与实际 dsh 用法脱节——执行者拿到 DISPATCH 后不知道具体怎么调 dsh 跑 A 类任务（chat 子命令不存在 + 工具默认禁用）。

**目标**：把 5 DISPATCH §6.2 从单姿势改成**三姿势候选**（dsh+override / REST API / 架构判定），并起草 `docs/m0b/` 下的 5 个真实可执行 spike runner 模板（4 yaml + 1 py）+ 更新 `docs/poll/cc-ready.json` 备注，让执行者按 DEEPSEEK_API_KEY 可用性 + 用户偏好选择执行路径。

**Codex 审验反馈（v0.0 → v0.1 修订源）**：
`notes/codex-review-v1.1-m0b-plan-report.md` 由 `gpt-5.6-sol` + `xhigh` 推理 给出 FAIL (CHANGES REQUIRED) 结论，包含 **2 critical + 7 major + 5 minor** findings。本 v0.1 修订针对每项 finding 给出修法。

### §6.X 三姿势候选（执行者按 DEEPSEEK_API_KEY 可用性 + 用户偏好选）

> 三路径 spike 实测并行设计 —— 三姿势候选方案基于 dsh 真实 CLI 探测（`@deepseek-ai/dsh` v0.1.1-rc.2）。

#### 姿势 A：dsh + profile override（v1.1 GA plan 钦定路径）

**前置**：
- `npm install -g @deepseek-ai/dsh`（v0.1.1-rc.2 / 455 packages / ~30s）
- `export DEEPSEEK_API_KEY=sk-...`
- 默认模型 = `deepseek-v4-flash`（等价类 commander/worker 档）；orch 档用 `deepseek-v4-pro`

**profile override（按本任务档位选 1 个 + 共用 base）**：
- `docs/m0b/profile-override-base.yaml` —— 启 `tool-bash` / `tool-fs` / `tool-fs-search` / `tool-str-replace-editor` / `tool-goal` / `tool-ralph` / `tool-subagent`；sandbox=workspace-write；telemetry=DISABLED；approval=ask
- `docs/m0b/profile-override-orch.yaml` —— model = `deepseek-v4-pro`（BE-1 用）
- `docs/m0b/profile-override-commander.yaml` —— model = `deepseek-v4-flash`（TG-1 / QA-1 用）
- `docs/m0b/profile-override-worker.yaml` —— model = `deepseek-v4-flash`（DO-1 / 摘要类用）

**跑命令（按档位 3 选 1）**：
```bash
# BE-1 orch (research)
time dsh --profile web \
  --patch docs/m0b/profile-override-base.yaml \
  --patch docs/m0b/profile-override-orch.yaml \
  -- "<具体 A 任务 prompt>"

# TG-1 commander (code-change) — dsh 默认模型即 v4-flash
time dsh --profile web \
  --patch docs/m0b/profile-override-base.yaml \
  --patch docs/m0b/profile-override-commander.yaml \
  -- "<具体 A 任务 prompt>"

# DO-1 worker (summary)
time dsh --profile web \
  --patch docs/m0b/profile-override-base.yaml \
  --patch docs/m0b/profile-override-worker.yaml \
  -- "<具体 A 任务 prompt>"
```

**trace 采集**：
- wall time：`time` 输出
- token 用量：dsh 内置 `token-meter` plugin 输出到 stderr；或读 `~/.dsh-home/sessions/<session-id>.jsonl`
- 退出码：`$?`

#### 姿势 B：DeepSeek REST API

**前置**：
- `export DEEPSEEK_API_KEY=sk-...`
- Python ≥ 3.10 + httpx（v1.0 runtime 已有 `httpx>=0.28,<0.29`）

**spike runner**：`docs/m0b/m0b-rest-spike.py`
- 端点：`https://api.deepseek.com/v1/chat/completions`（OpenAI 兼容）
- 3 等价类模型（per §2.3 MODELS 表）：orch = v4-pro / commander = v4-flash（默认）/ worker = v4-flash（vision-exp 作探索臂）
- 输出：stdout JSON + sidecar `.log`（含 per-run trace + retry 计数 + 失败 reason）
- 聚合：median(wall_s) / median(input_tokens) / median(output_tokens)
- 失败：全部 run 失败 → exit 1（不悄悄成功）
- 成本护栏：--max-tokens 默认 4096
- 重试：429/5xx + 网络错误 → 指数退避（2^attempt 秒），默认 2 次

**跑命令**：
```bash
python3 docs/m0b/m0b-rest-spike.py \
  --class commander \
  --task summary \
  --input /tmp/m0b-input-<role>.txt \
  --output /tmp/m0b-output-<role>.json
```

**姿势 B 适用边界（M5 修订）**：
- ✅ 文本型 A 类任务（research / summary）—— REST 单轮 chat completion 可验证模型能力
- ❌ code-change A 类任务（TG-1）—— REST 单轮无 tool loop，只能"单次吐代码块"，**无法真实验证改代码能力**。TG-1 的 H-1 覆盖率判定必须含姿势 A（dsh + override）
- ❌ multi-turn 研究 —— 单轮不覆盖
- 探索臂：`--model deepseek-v4-flash-vision-exp` 用于"看图"子任务，**不**作为 worker 档默认替代

#### 姿势 C：架构判定

执行者**不**直接填——由架构师在 A + B 数据回填后填：
- H-1 PASS（dsh + REST API 覆盖 ≥ 80% A 类任务）/ FAIL（≪ 80%）/ PARTIAL（80% 附近）
- H-1 FAIL → 启动「鱼之重新定义」专项（PRD-v1.1 §3 + DOCS-REVIEW §3 裁定 6 + NORTH-STAR §10 冲突 5）

|-----------------|---------|---------|------|
| 有 + 想验证 dsh 真实能力 | 任意 A | 姿势 A（主） + 姿势 B（对照） | 双路径互证 |

| 无 | — | 静态校验模板 + 报告"Not run: DEEPSEEK_API_KEY missing" | 不允许 hardcode key |
