## 流程纪律 (新增 — 2026-09-16, v1.4 修订强化)

> **新铁律**: 未来 cycle deploy 流程 = **归档 → Cline 审验 → deploy**. audit scope 文件 commit 到 git (notes/ 自伤豁免域) 作为可追溯 trail, deploy 必须在 Cline review PASS 后执行. **v1.4 强化**: archive commit (cycle closure) message **必须**含本 cycle 全量实测数 (v0.5 hard rule (d) 强制落地); feature commit message 含 "为什么 + what", 实测数可选. Cline 三审 F10 揭示: 前述 v0.5 rule 仅要求"附实测数"未规定哪个 commit, 导致 feature commit 标 ✅ 是"凭空捏造的'实测'反驳"。机制补丁 (v0.6 候选): 自检表 ✅ 必须 cat-file 实证, 不凭记忆。

**Why**: 之前 v1.2.0l cycle 闭流程是 "code → commit → deploy" 没审验 trail, deploy 失败要回滚 commit. 新流程让 audit-scope 文件本身就是 git 公民, 任何回归可 diff 到审验当时的预期 vs 实际. Cline 三审 v1.2.0n 暴露 audit-trail hygiene 自身需独立验证, 否则 recursive self-audit failure (closure 标 ✅ 但实测 ×)。

**How to apply**:
1. 写 `notes/cline-audit-scope-v<cycle>-m<module>-predeploy.md` (按 v0.5 hard rule 5 条 + 引用式纪律)
2. 让 Cline (VS Code extension) 审验 + 落 `notes/cline-review-v<cycle>-m<module>-predeploy-report.md`
3. Cline PASS 后才能 deploy (0 critical / 0 major / ≤ 2 minor sanity polish)
4. 归档 commit: audit-scope + report + closure 三件套 → **archive commit message 必须含本 cycle 全量实测数** → push via Clash proxy
5. **第二轮审**: 部署成功后, 再让 Cline 跑"收口审验" (review closure doc + archive commit 实测数 + deploy 内部自洽) — 这一层揭 self-audit failure (v1.2.0n 案例)
