## v0.6 流程纪律 (v1.0 强化)

> **未来 cycle deploy 流程**: 起草 audit-scope → Cline 审 → (修订如有) → 实施 commit → Cline audit-trail 二审 → cycle CLOSED → deploy。M1 是此流程的**首次完整闭环**: pre-implementation audit-scope 在 commit 之前起草 → Cline 审 → v1.1 修订 (5 findings) → 实施 commit 沿用修订后基线 → 实施未揭新 finding。

**Why**: v1.2.0l cycle 闭流程是 "code → commit → deploy" 无审验 trail, deploy 失败回滚 commit。v1.2.0n M0.1 retro-fit 5 轮 audit-trail 揭 1 major + 4 minor + 2 info (F10 伪引文 + F15 grep 计数错等), 反推 v0.6 候选机制 4 条。M1 是 pre-implementation audit-scope 流程的**首次实战**, 验证"事前审验"能将 self-audit failure 数量从 retro-fit 的 1 major 降到 pre-implementation 的 1 major (在 audit-scope 本身, 不在实施 commit)。

**How to apply**:
1. 任何 cycle 实施前必起草 `notes/cline-audit-scope-v<cycle>-m<module>-preimplement.md`
2. Cline 审 → 修订 (如有 findings)
3. 实施 commit message 必含 §修订元数据表 (含 Cline findings 全 FYI + 实施新 findings)
4. Cline audit-trail 二审 (审 实施 commit cat-file + §修订元数据表 + tag 锁定 + deploy 可行性) → PASS → cycle CLOSED → deploy
