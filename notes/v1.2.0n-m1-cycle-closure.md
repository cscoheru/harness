### v0.6 硬约束升级 (per R3 教训 — 第三次同型复发后必落地)

> **实证命令必须可原样复制粘贴运行**。具体:
> - 全局选项 (`--no-pager`, `-c`, etc.) **置于子命令前** (`git --no-pager diff`), 不是子命令后 (`git diff --no-pager A B` 是非法语法)
> - L8 grep 命中须**逐条列源** (行号 + 上下文 + 豁免类), 不允许只报计数 0 (R3 教训: 自检 "0" 可能是失败命令的空洞输出)
> - 测试 title-body invariant: 测试标题描述的行为必须实际被测试体断言 (R1 教训: T4 标题 "D skipped" 但测试体未让 B 失败, 标题-body 失洽 = 无效测试)
> - `cat-file 实测` 不可用声明替代 — 任何 "L8 = 0" 必须 cat-file 真跑 (`git --no-pager diff X Y -U0 | grep -cE ...`), 不能 "声明已 verify"

### 实施阶段测试 invariant (per R1 教训)

> 任何测试 title 中声称的行为必须在 `it` block 内被**真实断言**, 不允许 "verified in integration tests" 之类占位引用:
> - `it("D is skipped when B fails")` 必须有 mock 让 B 失败 + 断言 D 未被 dispatchStep 调用
> - 若当前实现**不**支持某行为 (如 M1.0 不阻断), 测试标题应改 "M1.0: D is STILL dispatched", 不是 "D skipped"

## v0.6 流程纪律 (v1.2 强化 — per R3 教训)

> **未来 cycle deploy 流程**: 起草 audit-scope → Cline 审 → (修订如有) → 实施 commit → Cline audit-trail 二审 → cycle CLOSED → deploy。M1 是此流程的**首次完整闭环**: pre-implementation audit-scope 在 commit 之前起草 → Cline 审 → v1.1 修订 (5 findings) → 实施 commit 沿用修订后基线 → **Cline 二审揭 3 major + 1 minor + 1 info (R1-R5), v1.2 fix-forward 处置 → Cline 三审** → cycle CLOSED。
