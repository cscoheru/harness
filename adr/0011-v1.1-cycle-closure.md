# ADR 0011: v1.1 cycle closure (single-host GA + 5 edge host 缺口挂账)

> **Status**: Accepted
> **Date**: 2026-09-02
> **Deciders**: fish-harness 架构师 + user（v0.5 升级 PASS 后 user 裁断路径选择）

## Context

v1.1 周期始于 M0b（commit `5b3d263`，ADR 0010 v1.1 cycle scope admission Accepted），经历 M0c（5 subagent 落地）+ M1c（DD-1 iPhone Safari E2E）+ M2（6 host 实施包 + v0.4 升级 hygiene 守门）三个里程碑，11 commits 链 + 5 commits v0.4 升级链 + v0.5 升级准备 = 21 commits。

M2 实施包设计了 6 host 拓扑（1 newvps 主 + 5 edge host east-1/west-1/asia-1/eu-1/sa-1），但 (b) 自部署评估（2026-09-02）实测：
- newvps `harness-kernel/wrapper/worker` 三容器 Up + Funnel `harness-newvps.tail1b9878.ts.net` 在线
- `tailscale status` 仅 2 节点（`harness-newvps` 100.103.132.72 + `fish-harness-newvps` 100.99.5.90），5 edge host 非真实机器
- server `/opt/puer-hub/.env` UNSET（DEEPSEEK_API_KEY / VAPID_PRIVATE_KEY / TAILSCALE_AUTH_KEY）

session 内 autonomous agent 无能力 provision VPS + 不持有 Tailscale auth key + 无 env vars，5 edge host 缺口**结构性不可达**。

M3 GA final 需 closure 决策：单 host v1.1 GA vs 6 host v1.1 GA。

## Decision

### Decision 1: v1.1 周期以单 host newvps 为 v1.1.0 GA 门槛（per 路径 A）

fish-harness on newvps 已 production-ready（容器 Up + Funnel 在线 + 11 commits 链 + v0.4 Codex formal PASS 0C/0M/0m），满足 v1.1.0 GA release 门槛（per ADR 0010 Decision (b)「GA final ≠ all features shipped」原则）。

### Decision 2: 5 edge host 缺口挂账 user 真实 provision（不阻塞 v1.1.0 GA tag）

5 edge host（east-1/west-1/asia-1/eu-1/sa-1）非真实机器，由 user 真实 provision（VPS 采购 + Tailscale 节点加入 + Funnel 配置 + Docker Compose 部署）。session 内 autonomous agent 不持有 provision 权限。

列入 v1.1+ 周期 roadmap：6 host v1.1.x patch 升级（M3 实施 + v0.6 audit-scope）。

### Decision 3: v0.5 audit-scope 守门机制落地（per v0.5 hard rule 5 条）

- (a) 先行起草 audit-scope §1/§1.5/§4.5/§6 在 commit 任何 audit-scope 引用文件之前
- (b) commit 后立即复审（commit 后 24h 内必跑 §2 验收命令矩阵）
- (c) 自引入预演入列 — 执行书/报告含 grep 字面时 commit 前必在 audit-scope §1.5 主表预演 #N+1 行
- (d) commit message 附实测数 — 必含 §1 锚定实测数
- (e) 引用式纪律（per Codex v0.4 §7.3 ② 升级）— prompt/报告凡引用锚定数字必走「audit-scope §1.5 主表唯一权威源」引用式，不复制绝对数字（防漂移回归）

## Alternatives

### Alternative 1: 6 host v1.1 GA（路径 B，备选）

**理由**：6 host 拓扑是 v1.1 architecture target，理应作为 v1.1.0 GA release 门槛。

**否决理由**：
- session 内 autonomous agent 无能力 provision 5 edge host + 不持有 Tailscale auth key + 无 env vars
- 5 edge host 缺口**结构性不可达**（per (b) 自部署评估）
- 单 host 已 production-ready，6 host 缺口挂账 user 不影响 v1.1.0 GA tag
- 等 user 真实 provision 6 host 完成再 tag，**v1.1 周期无限延长**（无强约束）

### Alternative 2: 不发 v1.1.0 GA tag（不推荐）

**理由**：保守起见，等 6 host 全部完成再发 v1.1.0。

**否决理由**：
- v0.4 Codex formal PASS 0C/0M/0m + 11 commits 链 + 锚定实测 107/46 三源同值 = 充分 release 门槛
- 单 host 已 production-ready
- 「不发 GA tag」 = v1.1 周期无 closure，违反 PRD-v1.1 §3 + NORTH-STAR §10 v1.1 GA plan 目标
- 6 host 设计是 architecture target 而非 release blocker（per ADR 0010 Decision (b)）

### Alternative 3: 单 host v1.1 GA 但不公开 5 edge host 缺口（不推荐）

**理由**：避免暴露 v1.1 实施期未完成项。

**否决理由**：
- 5 edge host 缺口是**结构性约束**（autonomous agent 无法 provision），不是实施失误
- 公开挂账 = 透明 + 真实 + 与 ADR 0010 Decision (b)「GA final ≠ all features shipped」自洽
- 不公开挂账 = 后续 6 host 实施时被 Codex 复审检出「5 host 设计 vs 单 host 实施」矛盾

## Consequences

### Positive

- v1.1 周期 closure 完成（per PRD-v1.1 §3 + NORTH-STAR §10 v1.1 GA plan 目标）
- 单 host v1.1.0 GA tag 可立即执行（user 亲提 `git tag -a v1.1.0` + push）
- 5 edge host 缺口透明挂账 v1.1+ 周期 roadmap
- v0.5 audit-scope 守门机制落地（5 条 hard rule + 引用式纪律），根治 9 次锚定漂移回归
- ADR ≥ 0010 冻结规则（T-DD-6）持续生效（v1.0 runtime 0 行 diff + 9 ADR body 不动）

### Negative

- 6 host 拓扑是 v1.1 architecture target，单 host v1.1.0 GA 不完全匹配 PRD-v1.1 §3 描述
- 5 edge host 缺口挂账 user 真实 provision，session 内无法完成
- 路径 A vs 路径 B 路径选择由 user 裁断，本 ADR 仅 closure Decision 1（路径 A）

### Neutral

- M3 GA final 实施步骤（per `docs/DISPATCH-T-M3-DISPATCH.md` §3 路径 A）：
  - M3-EXEC-1: 验证 server `.env` 含 DEEPSEEK_API_KEY + VAPID_PRIVATE_KEY
  - M3-EXEC-2: 真调 4 E2E 测试套件
  - M3-EXEC-3: 替换 webpush_gateway.ts hmacSha256() stub 为 ECDSA P-256 VAPID 签名
  - M3-EXEC-4: 验证 Funnel URL 6 路径全部返回 200
  - M3-EXEC-5: ADR 0011 closure 公告（CHANGELOG [1.1.0] + README v1.1 final 段 cross-ref）
  - M3-EXEC-6: **v1.1.0 GA tag**（user 亲提 + push）
