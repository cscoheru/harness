## Decision

v0.5 hard rule (candidates 4 条) 升级为 **v0.6 hard rule (3 条强制)**:

(a) **实证命令必须可原样复制粘贴运行** — 全局选项 (`--no-pager`,
`-c`, `-u`) **置于子命令前** (`git --no-pager diff A B`), 不是子命令后
(`git diff --no-pager A B` 是非法语法, git 报 usage 错, 输出为空,
管道后的 "0"/"X" 从未被测量). 例: `git diff 5912ddb 09e35f6 -U0 | grep -cE ...`
(✅ 正确) vs `git diff -U0 5912ddb 09e35f6 | grep -cE ...` (✅ 也正确) vs
`git diff 5912ddb 09e35f6 --no-pager -U0 | grep -cE ...` (❌ 非法语法)

(b) **L8 grep 命中须逐条列源** (行号 + 上下文 + 豁免类), **禁裸报 "0"**
— 自检 "0" 可能是失败命令的空洞输出 (per R3/T1 教训)。例: commit
message "L8 secrets: 0" 写之前必 cat-file 真跑, 然后**列出每个 range
的真值 + 每行 match 的来源** (closure 自引 / audit-scope 自引 /
commit message 自引 cat-file 命令文本 / sk-placeholder-edge{2,3} 占位符),
不允许只报一个"0"数字。

(c) **测试 title-body invariant** — 测试标题描述的行为必须在 `it`
block 内被**真实断言**, 不允许"verified in integration tests"之类占位引用
(per R1 教训: v1.2.0n M1 旧 T4 标题 "D skipped" 但测试体从未让 B 失败,
标题-body 失洽 = 无效测试)。任何测试标题 claim 行为未在断言体出现, 即
视为无效测试, 不计入 PASS 计数。

## Alternatives

- **A1: 维持 v0.5 candidate 不固化** — v0.6 仅是候选, 下 cycle 仍凭印象写。
  ❌（拒绝：4 次同型复发 (F10→F15→R3→T1) 已证 candidate 不够; 必须固化
  为 hard rule 才能让"计数真实 + 豁免列明"成为机制, 不是凭良心）
- **A2: 仅固化 (a) 实证命令可粘贴运行** — R3 教训最直接, 仅固化此条。
  ❌（拒绝：单条固化不足以打破同型复发循环; F10 (凭印象写"实测") 与
  R3 (凭印象写"0") 模式相同 — F10 是 (b) 失败, R3 是 (a) 失败;
  只固化 (a) 不固化 (b) 仍会复发）
- **A3: 固化全部 3 条 (本 ADR 决策)** — 全周期 audit-trail hygiene
  机制化, 下 cycle 起草 audit-scope / 实施 commit message / 测试
  rewrite 全部套用, 防止 4 次同型复发曲线复发。✅ 采纳。
- **A4: 升级为 v0.7 hard rule** — 加 (d) "audit-scope §修订元数据表必须
  含所有 findings 处置状态, 漏计显式标注" (per F17 v1.2.0n M0.1 闭环审验)。
  ❌（拒绝：(d) 在 v0.6 #4 已隐含, 不需独立规则; A3 范围够用, 留 (d)
  作为 v0.6 #4 子条款足够）

## Consequences

✅ v0.6 hard rule 落地 (`CLAUDE.md` §Hard Rule 章节 + ADR 0013) —
3 条强制机制 (a) 命令可粘贴 / (b) L8 列源禁裸报 / (c) title-body
invariant. 下 cycle (v1.2.0n M1.1) 起草 pre-implementation audit-scope
+ commit message + 测试 rewrite 全部套用.

✅ v0.5 hard rule (a-e: 先行起草 / commit 后立即复审 / 自引入不入
tracked / commit message 附实测数 / 引用式纪律) 保持 — v0.6 是 v0.5
之上的 audit-trail hygiene 增量.

⏸ M1.1 cycle (起草 audit-scope 时按 v0.6 起草) 仍需用户单独发
"Start v1.2.0n M1.1" — 本 ADR 不触发实际派发.

⚠ v0.6 hard rule 落地后, 若下 cycle 又翻车 (audit-scope / commit
message / 测试 中任一类同型复发), 立即升级 v0.7 加新约束 — 但仅在
证据充分时, 避免规则膨胀。

⚠ ADR 0013 是 v1.2.0n M1 cycle 沉淀, 不影响 v1.0 / v1.1 ADR
immutability. 引用本文时用 `<adr-0013>` tag.
