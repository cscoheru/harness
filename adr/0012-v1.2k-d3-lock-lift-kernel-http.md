# ADR 0012 — v1.2.0k D3 Lock Lift + Kernel HTTP Daemon

> **Status**: Accepted
> **Date**: 2026-09-13
> **Deciders**: fish-harness 架构师 + user
> **Supersedes**: (局部) — ADR 0010 Decision d 部分条款（v1.0 RUNTIME 0 行 diff gate 缩窄）

## Context

v1.1+ scope admission（ADR 0010 Decision a）已开 `harness/` 域（v1.2.0c D4/D5/D6 实证改了 `harness/runtime/{context_manager,context,worker_pool,workers}.py` + `harness/drivers/{codex_exec,codex_sdk}.py`），但 ADR 0010 Decision d 文字锁 `pyproject.toml` + `Dockerfile` + `docker-compose.yml`。v1.0 GA tag `ab8749a` 后 pyproject.toml 仅 2 commits（version bump + integration test），实质锁未破。

**wrapper → kernel HTTP 全链路缺口（v1.0 GA plan 漏掉的一环）**：

- `wrapper/orchestrator/orchestrator.ts:92-118` 已有 `kernelInvoke()`（POST /api/orch/invoke）客户端代码
- `wrapper/orchestrator/orchestrator.ts:130-149` 已有 `kernelStatus()`（GET /api/orch/status/{task_id}）客户端代码
- 注释明确说 "Real connection to v1.0 kernel HTTP API"（L6-9）
- **但 kernel 端从未实现这些路由** — `harness/__main__.py` 只 print version，`harness/server.py` 不存在，`Dockerfile` CMD 不启 daemon

**真问题**：
1. wrapper `kernelInvoke()` 永远走 fallback 分支（L118 `console.warn("kernel ${url} unreachable")`），**实际从未真打中过 kernel**
2. 用户/外部系统无法用 HTTP 触发 kernel driver-level invoke（multi-step 逻辑在 wrapper `commander.ts` 已存在）
3. wrapper j+.9+ 的 6host E2E 测试里，`/api/orch/cancel` + `/api/orch/list` 调的是 wrapper 本地，不是 kernel — kernel 链路 0 覆盖

## Decision

### Decision (a) — D3 LOCK LIFT（Full P0 + Infra scope）

v1.2.0k 起，以下 4 域开 v1.2+ 写权限：

- **`pyproject.toml`** — 加 fastapi + uvicorn 依赖（lift Decision d 部分条款）
- **`Dockerfile`**（root）— CMD 加 `[server,kernel]` 子命令 + 装 fastapi/uvicorn
- **`docker-compose.yml`** — 加 `kernel-http:4001` service + healthcheck（lift Decision d 部分条款）
- **`harness/`** — 新建 `harness/server.py` + `harness/runtime/orch_http.py` + 改 `harness/__main__.py`（Decision a 早已开）

**真不可动**（v1.0 GA 不可漂移，frozen 持续生效）：

- 9 ADR body（`adr/0001-0009*.md`）— immutable
- `spec/` — Protocol contract source（Decision d）
- `spikes/` — 历史 spike 不可改
- `_helpers.py` — Decision d 列锁
- `docs/v1.0-ga-team-plan.md` — immutable
- `harness/runtime/worker_pool.py` + `harness/runtime/workers.py` — NOT lift（driver pool primitives v1.0 stable，本次只 wrap 不重写）

### Decision (b) — Kernel HTTP Daemon contract

`harness/server.py` FastAPI app 暴露 5 routes：

| Route | Method | 用途 |
|-------|--------|------|
| `/api/orch/invoke` | POST | driver-level invoke + SSE 流式返回 driver events（mirror wrapper kernelInvoke L92-118 contract）|
| `/api/orch/cancel/{task_id}` | POST | 调 driver interrupt，按 cancel_token cascade AbortController.abort()（mirror wrapper cancel chain L556-573）|
| `/api/orch/list` | GET | 列 active tasks（from SQLite + InterruptRegistry）|
| `/api/orch/status/{task_id}` | GET | 单任务状态（mirror wrapper kernelStatus L130-149）|
| `/api/orch/healthz` | GET | kernel 健康检查（mirror wrapper health() L189-206）|

**multi-step 仍在 wrapper 端** — kernel HTTP daemon 是 driver-level 单步接口，multi-step logic 仍在 `wrapper/orchestrator/commander.ts`（per v1.2.0c D4/D5/D6 已实现的 cross-host dispatch + MacBook + host-id fencing）。本次只打通 HTTP 链路，不重做 multi-step planner。

### Decision (c) — Wrapper integration

wrapper 端 `kernelInvoke`（orchestrator.ts:92-118）+ `kernelStatus`（L130-149）+ `kernelHealth`（L189-206）**保留**。本次新增 `KERNEL_HTTP_URL` env var（默认 `http://kernel-http:4001`），fallback 行为不变（L118 warn + dsh fallback path 持续生效）。

### Decision (d) — Hygiene preserved

- L8 secrets：0 secrets in diff
- L19 sub-cycle hygiene：tag → commit 1 SHA（NOT cc-ready flip）
- D3 lock lift 不触 9 ADR body + v1.0 GA plan
- Codex 提交铁律（修订 2026-09-05）— Claude 可代劳 git tag + push via Clash proxy

## Alternatives

### Alternative 1 — 不做 D3 lift，继续 wrapper fallback

**否决理由**：kernel 永远无 HTTP 入口，wrapper j+.9+ 6host E2E 永远 cover 不到 kernel 链路。v1.0 GA plan 已声明要走 kernel HTTP（per wrapper orchestrator.ts L6-9 注释），永不落地 = 文档/代码 drift 持续扩大。

### Alternative 2 — Minimum（只 harness/ + pyproject.toml）

**否决理由**：Dockerfile 不改 → kernel daemon 启不来；docker-compose 不改 → wrapper 在容器内调不到 kernel。只 lift 2 域无法闭环。

### Alternative 3 — Chosen — Full P0 + Infra

**理由**：一次性打通 wrapper → kernel HTTP 全链路。后续 v1.2.0k+ 可在此基础上加 routes / 加 features（tenant isolation / persistent cancel queue / result blob storage）。11 files / +920 / -11 + 1 ADR + 1 tag + push via Clash proxy。

## Consequences

### Positive

- v1.0 → v1.2 全链路（HTTP → kernel driver → SSE 流回 wrapper）首次打通
- wrapper j+.9+ 6host E2E 可真测 kernel cancel/list 路径
- 用户/外部系统可用 HTTP 触发 kernel driver-level invoke（新 capability）
- ADR 0012 显式 lift D3 4 域 + NOT lift list，后续 v1.2+ 触及这 4 域不再走 D3 override（per-document 引用即可）

### Negative

- pyproject.toml + Dockerfile + docker-compose.yml 3 文件实质开 v1.2+ 写权限（但仍锁 9 ADR body + v1.0 GA plan）
- 新增 kernel-http daemon 容器需 ops 监控（healthcheck `start_period: 10s` + `interval: 5s`）

### Neutral

- `harness/runtime/worker_pool.py` + `harness/runtime/workers.py` 仍锁（Decision d 持续）— 本次只 wrap（新 `orch_http.py` 调既有 primitives），不重写
- multi-step logic 仍在 wrapper `commander.ts`（per v1.2.0c），kernel HTTP 只暴露 driver-level 接口
